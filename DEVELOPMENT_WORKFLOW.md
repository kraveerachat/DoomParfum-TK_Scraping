# TKS two-gate development workflow (proposed adoption)

## Intake
Inspect real repository, visibility, default/main SHA, local worktree if present, active PRs, approved plan and permissions. A=continue same task/branch/PR; B=new review unit; C=planning amendment; D=read-only. No duplicate PR for new session/agent. ChatGPT plans, Claude Code handles complex design/security, Codex bounded implementation; independent reviewer cannot self-attest. Tool decisions and exact evidence mandatory.
## Gate P / Gate I
Docs-only plan branch -> Draft planning PR -> owner review/merge -> verify merged SHA -> implementation branch from latest main -> TDD, focused/full regression, lint/type/build, negative controls -> docs and Draft PR -> independent review exact SHA -> immutable receipt when acceptance ready -> Owner review/merge -> post-merge reconciliation. Never merge as agent; no auto-merge or force-push. Material changes require C and Gate P again. No production deployment, data access or paid services implied by merge. Parent repository read-only unless separately authorized.
## Session records (parent §4.7)
Vault = Structure DB Obsidian. Each meaningful writable session creates one immutable full report in 08_Operations/Reports/TOPIC/YYYY-MM-DD_TASK_Sn_Report.md, one immutable separate summary in Summaries/TOPIC/YYYY-MM-DD_TASK_Sn_Summary.md, and appends session index to existing 07_Delivery/Tasks/TASK_slug.md, including SHA-256 of report/summary where available, actual Git state, evidence, decisions, blockers and next action. If hash or own commit cannot be computed before commit, say pending and record in subsequent PR/checkpoint. Do not edit prior reports; append corrections. Update status, decision/change/run logs, tool registry as relevant. No Downloads copies. Public-safe only; private original only in approved separate private vault; otherwise PRIVATE_RETENTION_NOT_CONFIGURED and omit sensitive material. Read-only reviewer writes nothing and provides independent report for separately authorized reconciliation.
## Git and reports
Use scoped authorized agent publishing identity; no credentials merely because available. Record branch/base/head, PR URL/state or blocker; no guessing. Stage exact paths, validate diffs, no unrelated changes. If tool cannot execute shell checks, mark NOT RUN. For every meaningful session record tool decision, task/topic/session, class, scope, actual commands/actions/files, test results/NOT RUN, failures, source rights, production NO, report and summary paths, evidence, next exact action. One final receipt per accepted task, not each session.
## Status
NOT STARTED, PLANNED, IN PROGRESS, BLOCKED, SOURCE IMPLEMENTED, LOCAL VERIFIED, ACCEPTANCE PENDING, READY FOR REVIEW, MERGED, CLOSED. Never infer implementation or deployment. Source rights gate separate from code gate. Parent import separate approval, staging and rollback.

## Master-plan execution and traceability (S2)
1. Intake: read master specification and applicable detailed contracts, direct requirement/test map, task map and actual current PRs. Record accepted plan SHA, predecessor merges, current branch/HEAD, exact task ID and permissions. Block if not verified.
2. Before changes: canonical task note records scope, exclusions, subtask IDs, expected evidence, paths, risks, tool decisions and source policy. User-approved scope only. No concurrent agents on same branch/files.
3. Implement bounded subtasks in listed order; tests target expected fixture behavior independent of implementation. Record observed RED/GREEN where applicable, exact commands/results, version and evidence. No fictitious test counts.
4. Checkpoint code plus Obsidian status, full report and separate summary, review actual diff/secrets/dependency changes. Record failures and not-run separately. If no shell access, mark shell checks NOT RUN.
5. Review exact PR SHA against master plan, relevant requirements and verification IDs. Independent reviewer records severity and path/line evidence; author cannot independently certify own security work. Resolve scope defects in same task PR; material changes require separate planning amendment.
6. Owner acceptance only: one receipt after task acceptance readiness, Owner alone merges. Reconcile status with actual merge SHA. Source rights, parent import and production approval are independent. Release acceptance is based on evidence, not line count or checklist completion by assertion.
