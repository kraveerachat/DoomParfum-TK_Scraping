# Agent and Local AI design
Three modes: Manual (no model), Agent (external Codex/Claude client), Local AI (LM Studio). All share Recipe/Source Policy/Job API; no model can grant rights or change budgets by itself.
MCP stdio tools (proposed): tk_list_sources, tk_list_recipes, tk_get_recipe, tk_pair_status, tk_inspect_tab (bounded DOM summary), tk_propose_selection (stable reference + highlight), tk_validate_recipe, tk_save_recipe (draft), tk_preview, tk_run, tk_status, tk_results (bounded pages), tk_export, tk_cancel. Inputs typed and reject unknown fields; output structured status/errors, jobId/recipeId and bounded sample. No arbitrary URL execution, file paths, shell, JavaScript or generic click; navigation only approved recipe actions. A user explicitly approves active tab and source, visible control and revoke. CLI config examples deferred until exact package/client versions checked. Codex skill plus MCP config, Claude Code skill/command plus MCP config; desired /tk-scrape shortcut where supported, fallback prompt 'Use tk-web-scraper tools...'. Do not assume same slash syntax, global install or cloud browser localhost access. Test both clients separately with fixture.
LM Studio provider: configurable loopback base URL (suggest default http://127.0.0.1:1234/v1, verify), /models discovery, /chat/completions structured JSON or tool calls; /responses optional if compatible. model ID user selectable, timeout/token/context budget, tool-call validation, bounded iterations, cancellation; local inference optional, never silently send to cloud. Small models may fail JSON/tool calls: fallback deterministic parser/manual review; no facts fabricated. Cloud agent may see approved minimized content only; no cookies, secrets, private DOM or forbidden source. Existing subscriptions used via legitimate installed clients, no API subscription equivalence assumed.
Evaluation: fixture gold recipes; compare field precision/recall, malformed output, latency, token budget, repair rate, refusal of injected page instructions. Model proposes selectors and semantic mapping, runner verifies actual DOM; deterministic run needs no model. Benchmark on user's actual host before selecting model/quantization. Never train on unlicensed content.
